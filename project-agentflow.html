The problem

Workflows need to remain secure, observable, and resumable.

A useful AI workflow system has to do more than arrange nodes visually. It needs to isolate organisations, execute real integrations, handle retries, pause for human approval, and keep long-running work observable without holding a browser request open.

What I built

Six node types and four trigger modes around a durable execution model.

01

Workflow nodes

LLM call, HTTP request, conditional branch, approval gate, database write, and notification.

02

Trigger paths

Manual, authenticated webhook, scheduled cron, and database-event execution.

03

Human approval

An approval node pauses execution and resumes the same run after an authorised decision.

04

Live status

GraphQL subscriptions stream step status into the interface without polling or refresh.

Architecture

Separate browser access, trusted execution, and durable workflow state.

Triggering a run authenticates the caller, reserves quota, snapshots the workflow, and returns a run ID. A Hasura Event Trigger starts the Nhost execution worker, allowing paused or longer workflows to remain durable and observable.

Security model

Organisation isolation is enforced beyond the interface.

Row-level permissions

Hasura permissions scope browser-facing data through organisation membership and the authenticated user ID.

Action checks

Protected workflow operations independently verify membership and role before elevated backend access.

Integration hardening

Hashed webhook secrets, SSRF/redirect protection, request timeouts, server-side secrets, retry tracking, and quota accounting.

What the live demo proves

The workflow visibly changes state and continues after approval.

The reviewer flow runs Gemini, branches on the result, conditionally performs an external POST, pauses at a human approval gate, resumes the same run, writes protected data, and records step updates through GraphQL subscriptions.
