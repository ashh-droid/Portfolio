Case study · Full-stack web application · 2026

Sweety

A responsive personal blood glucose logbook for entering up to four daily readings, exploring calendar and history views, and reviewing simple summary reports. The full-stack implementation emphasizes account isolation, input validation and clear, usable data entry.

The problem

Make repeated daily entries easy to review over time.

A useful personal logbook needs quick entry, a reliable way to edit mistakes, and an overview of days and months without losing track of individual readings. Sweety brings those workflows together in a responsive interface supported by a database-backed REST API.

User workflows

Four daily slots, calendar navigation and clear summary reports.

01

Daily reading entry

Users can add, edit and delete values in four defined slots: morning fasting, after breakfast, after lunch and after dinner.

02

History and calendar

A clickable monthly grid, grouped day history and older-history pagination make previous entries accessible.

03

Period summaries

Reports show reading counts, minimums, maximums and averages for a selected day, month to date and the previous full calendar month.

Account authentication uses bcrypt password hashes and JWTs in HTTP-only cookies. Readings and reports are scoped to the signed-in user. SQL constraints prevent duplicate readings for the same date and slot.

Input and data quality

Enforce the same data rules in the UI, API and database.

One entry per slot

Database uniqueness enforces one reading per user, calendar date and designated daily slot.

Practical input bounds

The application rejects future dates and values outside its implemented input range, returning readable validation errors.

Consistent calendar dates

Stored date strings and a configured application timezone avoid unintended day shifts when reading data.

Verification

Test date handling, validation and reporting behavior.

The project includes 33 standalone tests covering server-side validation and dates, calendar behavior, history averages and immediate reading-value checks. A separate PostgreSQL integration suite exercises authenticated HTTP endpoints and database-backed workflows when a disposable test database is configured.

Scope and limitations

A locally runnable software project, not a clinical device.

The repository provides setup instructions and real application screenshots; a public full-stack deployment is not claimed. Screenshots use fictional values. The illustrative reference band is not an individual health target, and the application does not provide diagnoses, treatment recommendations or medical advice.
