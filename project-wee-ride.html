The problem

Make everyday travel more shareable when traffic, cost, and rigid transport options create friction.

The project presentation frames the problem around heavy urban traffic, pollution, inconsistent public-transport schedules, and the cost of individual travel. It explores carpooling as a way to connect people travelling in compatible directions while making better use of existing vehicles.

The solution

Organize shared rides around clear driver, passenger, and administrator workflows.

WEE RIDE was developed as a web-based carpooling system with three primary roles. Drivers manage trip information and incoming ride requests, users search for available trips and request seats, and administrators monitor the system and manage application data.

Register→Search or offer ride→Request→Driver review→Ride history→Admin oversight

Engineering challenges

Coordinate multiple roles and ride states without turning research ideas into claimed implementation.

The source material does not document a bug-by-bug development diary, so these are the engineering challenges visible in the demonstrated system rather than invented incident stories.

01 · Multi-role workflow design

Drivers, passengers, and administrators need different screens and actions while still operating on the same ride and booking information.

02 · Ride and request state

The user journey spans ride discovery, a booking request, driver review, status updates, and ride history, which requires consistent state across several views.

03 · Frontend-backend-data flow

The project architecture connects browser interfaces to PHP/MySQL through HTTP requests, so forms, request handling, and stored records need to agree on the same data flow.
