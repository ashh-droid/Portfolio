Hostel Allocation System

The problem

Bring hostel applications, records, and room allocation into one system.

Disconnected manual steps make it difficult to track student requests, room availability, and allocation status. The application centralises those workflows with role-based access.

Application workflow

Separate experiences for students and administration.

Register or sign in→Submit request→Review records→Allocate room→View allocation

Student workflow

Authentication, hostel applications, status tracking, and allocation details.

Administration

Application review, student records, room allocation, dashboards, and allocation records.

Data model

Django ORM models cover users, student profiles, rooms, applications, and final allocations.

Application structure

Django authentication and ORM organise the application around clear domain entities.

Deployment work

Containerise the application and run it through Kubernetes resources.

The project includes Docker packaging and Kubernetes/Minikube resources for Deployments, Services, configuration, secrets, health probes, and replica scaling.

Docker

Packages the application and dependencies in a repeatable environment.

Kubernetes

Deployments and Services manage runtime instances and application access.

Reliability

Readiness/liveness probes, ConfigMaps, Secrets, and replicas support a more robust deployment model.

What I would improve next

Move the project closer to production conditions.

PostgreSQL, automated tests, CI/CD, stronger transaction handling, cloud deployment, and centralised monitoring are the next logical improvements.
